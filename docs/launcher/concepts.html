Launcher Concepts

Your screenshot is rofi: "Type to filter" and the italic "(Web Browser)" generic names are its defaults. Rofi 2.0 (September 2025) merged the Wayland port, so the same tool and the same rofi -dmenu scripts you used under i3 run natively on Hyprland. Three directions below, drawn in the Quasar palette. Each one uses only effects rofi and Hyprland can render; the table under each mock says how.

Glass and Rim are for apps; Horizon line is the companion theme for scripted menus. A typical pick is one of the first two plus Horizon. Contrast check: body text 13.5:1 / Lc 88 on the panel; dark text on the red mode pill 8.7:1.

Pop-inlayer rule animation = "popin 92%"

Why pick it

  • Most "space" when your wallpaper is a nebula: the blur shows it.
  • Readability depends on what is behind the panel. The 78% body keeps text above contrast rules over any wallpaper; lower opacity is not safe.

Limit

The gradient can only be a bar, not a full frame: in rofi a gradient frame sits behind the body, so a translucent body would show the gradient instead of the blurred desktop.

Why pick it

  • Fully predictable contrast: nothing shows through.
  • The gradient frame is the "fancy border" you asked for.

Limit

No glow or drop shadow: neither rofi nor Hyprland layer rules draw shadows around layers. The rim and the dim are the substitutes.

Why pick it

  • Exactly how dmenu felt in i3; zero visual noise.
  • Every rofi -dmenu script uses this theme via -theme horizon.

Limit

Not meant for app launching with icons; it is the companion theme for scripts.

Menus built on it

One engine (rofi) for everything; i3-style default keys. Each scripted menu is a small bash script that pipes into rofi -dmenu, so anything you wrote for dmenu in i3 keeps working.

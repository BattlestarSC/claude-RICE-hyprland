# hypr\* ecosystem tools

## Key fact: two config languages in one rice

Hyprland itself is Lua-only from 0.57. Its companion tools still read **hyprlang** `.conf`
files. Both live in `~/.config/hypr/`. [V: hyprland-wiki `hypr-ecosystem/user/*.md`, 2026-10-29]

| Tool | Config file | Format | Required? | Role in this rice |
| --- | --- | --- | --- | --- |
| Hyprland | `hyprland.lua` | Lua 5.5 | autogenerated if missing | compositor |
| hyprlock | `hyprlock.conf` | hyprlang | **yes: exits with error if missing, session stays unlocked** | lock screen |
| hypridle | `hypridle.conf` | hyprlang | **yes: won't run without one** | idle → dim → lock → dpms off → suspend |
| hyprpaper | `hyprpaper.conf` | hyprlang | no | wallpaper |
| hyprtoolkit | `hyprtoolkit.conf` | hyprlang | no | theme for hyprtoolkit GUI apps (launcher, polkit dialog) |
| hyprlauncher | `hyprlauncher.conf` | hyprlang | no | app launcher candidate (always a daemon) |
| hyprpolkitagent | `~/.config/hyprpolkitagent/hyprpolkitagent.conf` | hyprlang | no | polkit auth dialog |
| hyprsunset | `hyprsunset.conf` | hyprlang | no | blue-light filter (optional) |
| hyprshutdown | CLI flags | n/a | n/a | graceful logout/shutdown UI |
| xdg-desktop-portal-hyprland | `xdph.conf` | hyprlang | no | screenshare, global shortcuts |

Theme generation therefore needs **two output formats per palette**: a Lua table for
Hyprland and a hyprlang variable file for the others.

## hyprlang essentials (for the `.conf` tools)

[BK; consistent with every example in the current wiki]

```ini
$accent = rgba(7FD7E6ff)          # variables start with $
source = ~/.config/hypr/theme/colors.conf   # include; globbing and ~ supported (hyprpaper doc [V])

general {                          # categories are braces
    hide_cursor = true
}
# comments with '#'; colors use the same formats as Hyprland (rgba(), rgb(), 0xAARRGGBB)
```

## hyprlock

- Search order: `$XDG_CONFIG_HOME/hypr/hyprlock.conf`, `~/.config/hypr/hyprlock.conf`,
  each `$XDG_CONFIG_DIRS/hypr/hyprlock.conf`, `/etc/xdg/hypr/hyprlock.conf`. First match wins.
- **Failure mode:** if no config is found it exits non-zero and nothing is locked. A lock bind
  or hypridle `lock_cmd` pointing at hyprlock is only safe once the config is deployed.
- Useful flags: `--grace N`, `--immediate-render`, `--no-fade-in`, `-c <file>`.
- Can read keyboard layout from Hyprland settings (`$LAYOUT[...]`).

[V: hyprland-wiki `hypr-ecosystem/user/hyprlock.md`, 2026-10-29]

### Lock screen (this rice: `config/hypr/hyprlock.conf`)

Read from hyprlock's source at `a9e26af` (2026-10-29) unless noted. [V: source]
- **Config errors are not fatal**: hyprlang errors are logged ("Proceeding ignoring faulty
  entries") and the lock still starts. Only a *missing* file is fatal (wiki).
- `~` in `path` is expanded (`absolutePath`). A background image that is missing or fails to load
  becomes an invalid texture and the widget draws `color` instead; locking is unaffected.
- Outputs are bound from registry globals as they appear and dropped on removal, so a KVM
  switch back adds lock surfaces for the returning monitors [behavior on hardware: TODO-verify].
- `animation = fadeIn, 0` is accepted (on/off 0 disables). Every key in our file was checked
  against `addConfigValue` / `addSpecialConfigValue` in `src/config/ConfigManager.cpp`.
- PAM service `hyprlock`; Arch's `pambase` faillock: 3 failures → 10 min lockout (wiki).
- Security properties come from `ext-session-lock-v1`: while locked only lock surfaces are drawn
  (windows, notifications and the bar are not), and if the locker dies the session stays locked
  behind the red "lockdead" screen. `misc.allow_session_lock_restore = true`
  (`config/hypr/conf/session.lua`) lets a new hyprlock take over from a TTY:
  `hyprctl --instance 0 eval 'hl.exec_cmd("hyprlock")'` [V: wiki `--instance` + `eval` usage].
- Design: still ASCII sky (`~/.local/share/rice/lock.png`, rendered by the installer) dimmed by a
  full-screen `$crust` shape at 45 %, mono clock, date, password field with the Orbit frame
  (red → purple), yellow while checking, orange on Caps Lock, PAM failure text with attempt count.

## hypridle

Upstream-recommended structure [V: hyprland-wiki `hypridle.md`, 2026-10-29]:

```ini
general {
    lock_cmd = pidof hyprlock || hyprlock          # single instance
    before_sleep_cmd = loginctl lock-session       # every sleep path goes through logind PrepareForSleep
    after_sleep_cmd = hyprctl dispatch 'hl.dsp.dpms({ action = "enable" })'
}
listener { timeout = 150;  on-timeout = brightnessctl -s set 10;   on-resume = brightnessctl -r }
listener { timeout = 300;  on-timeout = loginctl lock-session }
listener { timeout = 330;  on-timeout = hyprctl dispatch 'hl.dsp.dpms({ action = "disable" })'
                           on-resume  = hyprctl dispatch 'hl.dsp.dpms({ action = "enable" })' && brightnessctl -r }
listener { timeout = 1800; on-timeout = systemctl suspend }
```

(Shown compressed; real hyprlang needs one key per line.)

Design points:
- The locker is named in exactly one place (`lock_cmd`); everything else calls
  `loginctl lock-session`. Our lock keybind must do the same.
- Video players hold Wayland idle inhibitors; this pauses **all** listeners.
- Lid handling belongs to logind (`HandleLidSwitch`), not Hyprland.
- Note the **new `hyprctl dispatch` Lua syntax** in the dpms commands.
- Hooks used here: `on_lock_cmd` / `on_unlock_cmd` (fire when a session-lock client locks or
  unlocks) pause and resume the animated wallpaper over Quickshell IPC.
- This rice (`config/hypr/hypridle.conf`): lock at 10 min, DPMS off at 11 min, **no automatic
  suspend** (Blender renders do not inhibit idle). The screensaver slot at 5 min is pending (O14).

## hyprpaper

Current syntax uses `wallpaper { }` blocks [V: hyprland-wiki `hyprpaper.md`, 2026-10-29]:

```ini
splash = false
wallpaper {
    monitor =                 # empty = fallback for all monitors
    path = ~/.local/share/<rice>/wallpapers/nebula.png
    fit_mode = cover          # contain | cover | tile | fill
}
```

`path` may be a directory (rotates every `timeout` seconds, `order = random`). The older
`preload = ...` / `wallpaper = MONITOR,path` syntax from pre-2026 guides is outdated.
Relative paths resolve against hyprpaper's working directory, so always use absolute or `~` paths.

## hyprtoolkit (theme source for hypr GUI apps)

`~/.config/hypr/hyprtoolkit.conf` [V: hyprland-wiki `hyprtoolkit.md`, 2026-10-29]:

| Key | Default | Map from palette |
| --- | --- | --- |
| `background` | `0xFF181818` | `base` |
| `base` | `0xFF202020` | `mantle` |
| `alternate_base` | `0xFF272727` | `surface0` |
| `text` | `0xFFDADADA` | `text` |
| `bright_text` | `0xFFFFDEDE` | `bright` |
| `accent` | `0xFF00FFCC` | primary accent (border gradient start) |
| `accent_secondary` | `0xFF0099F0` | border gradient end |
| `font_family`, `font_family_monospace`, `icon_theme` | | rice fonts / icon theme |
| `rounding_large`, `rounding_small` | 10 / 5 | match Hyprland `decoration.rounding` |
| `h1_size` … `small_font_size` | | leave default unless HiDPI testing says otherwise |

Apps documented as following this theme: hyprlauncher, hyprpolkitagent. Others built on
hyprtoolkit (hyprshutdown, hyprpwcenter, hyprland-guiutils dialogs) very likely do too [BK].

## hyprlauncher

- Always a daemon; `hyprlauncher -d` starts it without showing a window. Bind the plain command to a key.
- Finders: `desktop` (default), `math` (`=`), `unicode` (`.`), font (`'`).
- `desktop_launch_prefix` exists for `uwsm app -- `.
- Stores usage history in plain text in `~/.local/share/hyprlauncher` (cache `enabled = true` by default).
- Hyprland's emergency bind `SUPER+R` launches it.

[V: hyprland-wiki `hyprlauncher.md`, 2026-10-29]

## hyprpolkitagent

Start from autostart: `systemctl --user start hyprpolkitagent`. Without a polkit agent, GUI apps
that need elevation fail silently or hang. [V: hyprland-wiki `hyprpolkitagent.md`, 2026-10-29]

## xdg-desktop-portal-hyprland (XDPH)

- Provides screen sharing and global shortcuts. **No file picker:** install
  `xdg-desktop-portal-gtk` alongside it.
- Screen sharing needs `pipewire` + `wireplumber` running; monitor `bitdepth` must match the panel.
- Xwayland apps can only capture Xwayland windows.

[V: hyprland-wiki `xdg-desktop-portal-hyprland.md`, `screen-sharing.md`, 2026-10-29]

## hyprshutdown

Recommended way to exit Hyprland: asks apps to close gracefully instead of killing them.
`hyprshutdown -t 'Shutting down...' --post-cmd 'shutdown -P 0'`. The upstream example falls back
to `hyprctl dispatch 'hl.dsp.exit()'` when it is not installed.
[V: hyprland-wiki `hyprshutdown.md`; Hyprland v0.57.0 `example/hyprland.lua`, 2026-10-29]

# Hyprland (target: 0.57.x, Lua config)

## TL;DR

- Hyprland **0.57.0 (2026-10-28) dropped the hyprlang `hyprland.conf` format.** The only
  supported config is Lua: `$XDG_CONFIG_HOME/hypr/hyprland.lua`. [V: hyprland-wiki
  `configuring/core/_index.md`, 2026-10-29] [S: hypr.land news "update57", linuxcompatible.org, 2026-10-29]
- Lua config was introduced in **0.55 (2026-05-09)**; 0.55 and 0.56 accepted both formats.
  0.56 shipped 2026-07-20. [S: hypr.land news "update55", search summary, 2026-10-29]
- There is **no official converter** from `.conf` to `.lua`. [S: linuxcompatible.org; GitHub discussion hyprwm/Hyprland#14463]
- The rest of the hypr\* ecosystem (hyprlock, hypridle, hyprpaper, hyprtoolkit, hyprlauncher)
  **still uses hyprlang `.conf`**. See [hypr-ecosystem.md](hypr-ecosystem.md).
- Embedded Lua is **5.5** (`CMakeLists.txt` requires `lua>=5.5 <5.6`). [V: Hyprland v0.57.0 source, 2026-10-29]
- Arch `extra` status at time of writing: `hyprland 0.56.2-4` published; packaging tag
  `0.57.0-1` pushed 2026-10-28. [S: archlinux.org package page and arch-commits list via search, 2026-10-29]
  The installer must check the installed version (see [Version gate](#version-gate)).

## Mental model

The config file is a Lua program that Hyprland executes. It does not declare state the way
hyprlang did; it **calls API functions** (`hl.config`, `hl.bind`, `hl.window_rule`, ...)
that register state with the compositor. Consequences:

- Order matters. For options, the last `hl.config` write to a key wins.
- Expressions in arguments are evaluated **once, at load time**. Anything that must be
  evaluated per keypress belongs inside a `function() ... end` passed to `hl.bind`.
- The full Lua standard library is available (`os`, `io`, ...). The config is arbitrary
  code execution as the user. Never source untrusted Lua.
- Callbacks (binds, `hl.on` event handlers) run **on the compositor's event loop**. A
  blocking call freezes input for the whole desktop. Use `hl.dsp.exec_cmd(...)` for
  anything external.

## Files, loading, reload

| Item | Value |
| --- | --- |
| Config path | `$XDG_CONFIG_HOME/hypr/hyprland.lua` (normally `~/.config/hypr/hyprland.lua`) |
| Override path | `start-hyprland -- --config <path>` or env `HYPRLAND_CONFIG` |
| Missing config | Hyprland writes the upstream example and shows an "autogenerated" banner; remove `hl.config({ autogenerated = true })` to clear it |
| Reload | Automatic on file change; manual `hyprctl reload`; from Lua `hl.reload_config()` (0.57+, [S]) |
| Launcher binary | `start-hyprland` (args to Hyprland go after `--`). Do not run as root. |
| Validate | `Hyprland --verify-config` flag exists in v0.57.0 `src/main.cpp` [V]. Whether it works without a running session/GPU is **[TODO-verify]**. |
| LSP stubs | `/usr/share/hypr/stubs/` → add to `.luarc.json` `workspace.library` |

All of the above: [V: hyprland-wiki `configuring/core/_index.md`, `getting-started/master-tutorial.md`, 2026-10-29].

The installer **copies** the config (D29), so whether the file watcher follows symlinks no longer

`hyprctl reload` always works.

### Splitting the config (`require`)

- `require("theme.colors")` resolves relative to the directory of `hyprland.lua`. `.` or `/`
  as separator; `.` preferred for relative modules.
- Wildcards: `require("./conf.d/*")` loads every file in a directory. Paths with `*` must be UNIX-style.
- Hyprland wraps `require` so **each required file is its own error scope**: a runtime error
  in `binds.lua` does not stop `rules.lua` from loading.
- Exception: `require` of a **nonexistent** module throws in the caller and kills the caller's
  execution. Guard optional modules with `pcall(require, "local")`.
- Unwrapped Lua `require` is available as `__require`.

[V: hyprland-wiki `configuring/core/_index.md`, 2026-10-29]

Layout of this repo's config (2026-10-30; `input.lua`, `rules.lua`, `autostart.lua`, `env.lua` added):

```text
~/.config/hypr/
├── hyprland.lua          # entry point: only require() calls, in a fixed order
├── theme/colors.lua      # generated from the chosen palette; returns a table
├── conf/
│   ├── binds.lua         # loaded first: a terminal bind exists even if a later file fails
│   ├── env.lua           # toolkit backends, XDG_MENU_PREFIX, cursor (installer sets the name)
│   ├── monitors.lua      # panels by EDID description (rice-monitors fills them in)
│   ├── input.lua         # layout us, focus follows mouse, pointer hides after 10 s
│   ├── look.lua          # general/decoration/animations
│   ├── layers.lua        # blur/animation per shell surface namespace
│   ├── rules.lua         # window rules (below)
│   ├── session.lua       # lock-screen recovery
│   └── autostart.lua     # hl.on("hyprland.start"): polkit agent, quickshell, hypridle, cliphist
└── local.lua             # user overrides, never overwritten by the installer, loaded via pcall
```

### Error behavior

- Lua **syntax** error: Hyprland refuses to load/reload and shows an error.
- Lua **runtime** error (e.g. calling `nil`): aborts the current file, shows an error.
- Hyprland **type** error (wrong type into `hl.*`): logs an error, execution continues.
- Error inside an async callback (bind, event): notification.
- If an error happens **before any bind is registered**, Hyprland installs emergency binds:
  `SUPER+Q` terminal, `SUPER+R` hyprlauncher, `SUPER+M` exit. Our entry point should register
  a minimal "escape hatch" bind set first, in its own file, so a broken later module never
  leaves the user without a terminal.

## API surface used by this rice

Verified against the upstream example config at tag `v0.57.0` (`example/hyprland.lua`) and the
wiki at 2026-10-29 unless noted.

```lua
-- Options: nested tables, or dotted keys
hl.config({ general = { gaps_in = 5, gaps_out = 20, border_size = 2, layout = "dwindle" } })
hl.config({ ["decoration.rounding"] = 10 })

-- Colors and gradients
hl.config({ general = { col = {
    active_border   = { colors = { "rgba(33ccffee)", "rgba(00ff99ee)" }, angle = 45 },
    inactive_border = "rgba(595959aa)",
} } })

hl.monitor({ output = "", mode = "preferred", position = "auto", scale = "auto" })
hl.env("XCURSOR_SIZE", "24")   -- use os.getenv() to reference existing vars

hl.on("hyprland.start", function()
    hl.exec_cmd("waybar")
end)

hl.curve("easeOutQuint", { type = "bezier", points = { {0.23, 1}, {0.32, 1} } })
hl.curve("easy", { type = "spring", mass = 1, stiffness = 238.1191, damping = 24.21279333 })
hl.animation({ leaf = "windowsIn", enabled = true, speed = 4.1, spring = "easy", style = "popin 87%" })

local mainMod = "SUPER"
hl.bind(mainMod .. " + Q", hl.dsp.exec_cmd("kitty"))
hl.bind(mainMod .. " + mouse:272", hl.dsp.window.drag(), { mouse = true })
hl.bind("XF86AudioRaiseVolume", hl.dsp.exec_cmd("wpctl set-volume -l 1 @DEFAULT_AUDIO_SINK@ 5%+"),
        { locked = true, repeating = true })

hl.window_rule({ name = "float-pavucontrol", match = { class = "^(pavucontrol)$" }, float = true })
hl.layer_rule({ match = { namespace = "waybar" }, blur = true })
hl.workspace_rule({ workspace = "w[tv1]", gaps_out = 0, gaps_in = 0 })

hl.gesture({ fingers = 3, direction = "horizontal", action = "workspace" })
hl.device({ name = "epic-mouse-v1", sensitivity = -0.5 })
```

### Color value formats

`"#RRGGBB"`, `"#RRGGBBAA"`, `"#RGB"`, `"rgba(RRGGBBAA)"`, `"rgba(r,g,b,a)"`, `"rgb(RRGGBB)"`,
`"rgb(r,g,b)"`, legacy `"0xAARRGGBB"` (note: **alpha first** in the legacy form; the upstream
example also passes a bare integer `0xee1a1a1a` for shadow color). No spaces inside `rgb()`.
Gradients: a color, or `{ colors = { c1, c2, ... }, angle = deg }`.
[V: hyprland-wiki `configuring/naming-conventions.md`, 2026-10-29]

Our generated `theme/colors.lua` should emit `"rgba(RRGGBBAA)"` strings: unambiguous byte
order, alpha explicit, accepted everywhere a color is.

### Binds

- Signature: `hl.bind("MODS + key", dispatcher_or_function, { flags })`. Returns a handle with
  `:set_enabled(bool)`, `:unbind()`, `:remove()`.
- `hl.unbind("KEY")` is **case-sensitive** against the original string.
- `hl.dsp.*` functions only **build** an action table. Inside a function you must call
  `hl.dispatch(hl.dsp.foo())`; a bare `hl.dsp.foo()` does nothing.
- Conditions written inline are evaluated at config load, not per press. Wrap them in a function.
- `auto_consuming = true` + `return { ok = false }` passes the key through to the app.
- Keycodes: `"SUPER + code:28"`. Modifier-only binds via keysyms: `"Super_L"`.
- Find key names with `wev`.

[V: hyprland-wiki `configuring/core/binds/_index.md`, `dispatchers.md`, 2026-10-29]

### Window rules (Lua form, 0.55+)

- `windowrulev2` is gone (0.53 rewrote rules); since 0.55 they are written as `hl.window_rule({ match = {...}, effect = value })`.
- Match props: `class`, `title`, `initial_class`, `initial_title` (RegEx), `float`, `fullscreen`,
  `pin`, `focus`, `group`, `modal`, `xwayland`, `workspace` (selector), `tag`, `content`, `xdg_tag`.
- **Static effects** (`float`, `size`, `move`, `workspace`, `monitor`, `center`, ...) are evaluated
  once at window open, against the initial class/title. Title changes after open never trigger
  them. Use `hl.on("window.title", ...)` + `hl.dispatch` for that.
- **Dynamic effects** (`opacity`, `no_blur`, `border_size`, `rounding`, ...) are re-evaluated.
- `size`/`move` accept `{ w, h }` or `"w h"` (whitespace only; `"800x600"` is an error) and
  expressions such as `"monitor_w*0.5"`.
- Rules return handles (`:set_enabled(false)`).

[V: hyprland-wiki `configuring/core/rules/window-rules.md`, 2026-10-29]

### Events (`hl.on`)

Useful ones: `hyprland.start`, `hyprland.shutdown`, `config.reloaded`, `config.unload` (0.57),
`monitor.added`/`removed`, `window.open`, `window.title`, `window.active`, `workspace.active`,
`keybinds.submap`, `screenshare.state`.
[V: hyprland-wiki `configuring/core/advanced-configuration/events.md`, 2026-10-29]

### hyprctl changed too

`hyprctl dispatch` now takes a **Lua dispatcher expression**:

```sh
hyprctl dispatch 'hl.dsp.focus({ workspace = "3" })'
hyprctl dispatch 'hl.dsp.dpms({ action = "disable" })'
hyprctl eval 'hl.config({ ["general.gaps_in"] = 10 })'   # runtime-only, lost on reload
hyprctl repl 'hl.get_active_window().class'
```

Old-style `hyprctl dispatch workspace 3` / `hyprctl keyword general:gaps_in 10` from older
scripts, waybar configs and hypridle examples will not work. Every script and every
`on-click` in the bar must use the new form.
[V: hyprland-wiki `using-hyprctl.md`, `hypridle.md`, 2026-10-29]

## Version gate

The installer must refuse to deploy the Lua config to a Hyprland that cannot load it, and
should warn when the API may differ from what was tested:

```sh
# `Hyprland --version` prints a human-readable block; --version-json exists in v0.57.0 main.cpp [V].
# Exact JSON field names: [TODO-verify] on a real install before relying on them.
Hyprland --version-json
```

Policy: minimum **0.57.0**. 0.55/0.56 accept Lua too, but the Lua API was young then and
changed between releases [S]; supporting them is not worth the test matrix.

## Common pitfalls (checklist for every config change)

1. Copying hyprlang syntax (`bind = SUPER, Q, exec, kitty`, `$var =`, `windowrulev2`) into Lua.
2. Calling `hl.dsp.*` inside a function without `hl.dispatch(...)`.
3. Blocking work (`io.popen`, `os.execute`, `sleep`) inside a bind or event callback.
4. Inline conditions in `hl.bind(...)` arguments that should be evaluated per press.
5. `require` of an optional file without `pcall`.
6. Old `hyprctl dispatch <name> <args>` syntax in scripts, bar modules, hypridle.
7. Assuming a static window rule re-applies after a title change.
8. Placing Wayland env vars in `/etc/environment` (breaks other sessions); use `hl.env`.

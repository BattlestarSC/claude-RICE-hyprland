# The i3 desktop (X11): FreeBSD's default

D43. The rice's look and keys on X11 for FreeBSD, where the Wayland stack works but is the
less-travelled path (no greetd, no logind, Hyprland only through a port overlay we maintain).
Everything here is a FreeBSD binary package; nothing is compiled. `RICE_DESKTOP=hyprland`
(or the plan's first question) still installs the Hyprland desktop on FreeBSD.

Labels: [V] verified against a primary source or a run (date), [BK] background knowledge,
[TODO-verify] not yet checked.

## Session flow

```text
LightDM (rc: lightdm_enable) ─ greeter: lightdm-gtk-greeter, theme Quasar-greeter
  └─ session rice-i3 ─ /usr/local/etc/lightdm/Xsession (sources ~/.profile, ~/.xprofile)
       └─ /usr/local/libexec/rice-i3-session ─ ~/.local/bin/rice-session i3
            ├─ . ~/.config/i3/env.sh   PATH, XDG_*, QT_QPA_PLATFORMTHEME=qt6ct, cursor
            └─ dbus-run-session i3
                 ├─ exec rice-session x11       picom, dunst, polkit agent, clipmenud, xss-lock
                 ├─ exec_always rice-bar launch polybar main (primary) / side (others)
                 └─ exec_always feh             wallpaper
```

- **Why a launcher file in `libexec`:** the FreeBSD port's `Xsession` ends in `exec $@`
  (unquoted, word-split), so `Exec=sh -c '...'` in the `.desktop` entry would break [V:
  freebsd-ports `x11/lightdm/files/Xsession.in`, 2026-10-31]. It also sources every file in
  `/usr/local/share/xsessions` whose name has no dot; `rice-i3.desktop` has one.
- **Config drop-ins:** LightDM reads `lightdm.conf.d/*.conf` in `/usr/local/etc/lightdm` before
  `lightdm.conf` [V: lightdm `common/configuration.c`, `config_load_from_standard_locations`];
  lightdm-gtk-greeter reads `lightdm-gtk-greeter.conf.d/*.conf` before its main file [V:
  `src/greeterconfiguration.c`]. The rice writes only `50-rice.conf` in each, so the package's
  files stay untouched and an owner's setting in the main file still wins.
- **Greeter look:** its widgets are styled by the GTK theme named in `theme-name`; the greeter
  adds its own small CSS at APPLICATION priority [V: `lightdm-gtk-greeter.c`]. The rice installs
  the theme `Quasar-greeter` (`/usr/local/share/themes/Quasar-greeter/gtk-3.0/gtk.css`: imports
  adw-gtk3-dark, then the glass card) and copies the background to
  `/usr/local/etc/lightdm/rice/background.png` (the greeter runs as user `lightdm`).
- **Keyring:** `pam_gnome_keyring` added to `/usr/local/etc/pam.d/lightdm` (installed by pkg
  from `lightdm.sample`) by the same awk edit as greetd's, with the module's full path
  `/usr/local/lib/pam_gnome_keyring.so` [V: freebsd-ports `security/gnome-keyring/pkg-plist`].
  Whether OpenPAM would also find it by bare name: [TODO-verify]; the full path works either way.
- **LightDM's other dependencies** (ConsoleKit2, accountsservice) come with the package
  [V: port Makefile]; `dbus_enable` is set by the installer.

## Facts and gotchas

- **i3:** `include` of a path that matches no file is silently skipped [V: `i3 -C` with a
  missing include exits 0, i3 4.23]; `i3 -C -c FILE` exits 1 on any parse error [V]. So
  `~/.config/i3/local.conf` is optional. Variables set in an included file are not visible in
  the parent (i3 user guide, include) [BK].
- **Gaps and the bar:** i3 places a managed dock window at full output width, ignoring polybar's
  `offset-x` / `width` [V: Xvfb screenshot]. The floating glass bar is therefore
  `override-redirect = true` + `wm-restack = i3`, and i3 leaves room with `gaps top 38px`
  (6 px offset + 32 px bar). polybar warns that `wm-restack` is ignored without override-redirect.
- **polybar:** a missing `include-file` is fatal ("Failed to open config file") and relative
  paths resolve against the including file's directory [V: polybar `config_parser.cpp`]; the
  installer creates an empty `local.ini`. Colors are `#AARRGGBB` (template filter `qcolor`).
  The built-in `cpu`, `memory` and `fs` modules read `/proc` [V: `src/modules/fs.cpp` reads
  `/proc/self/mountinfo`]; the rice uses `custom/script` modules running `rice-bar`.
- **Script output into a pipe:** awk block-buffers when stdout is a pipe, so a tail-mode module
  printing through awk shows nothing [V: `rice-bar cpu | head` printed nothing until awk
  printed with the shell]. `rice-bar cpu` prints with `printf`.
- **awk `printf` with `>`:** in an unparenthesized `printf` argument list, `>` is output
  redirection (`printf "%d", t > 0 ? a : b` wrote a file named `0`) [V]. Parenthesize
  conditionals in awk `printf`/`print`.
- **FreeBSD stats:** CPU from `sysctl kern.cp_time` (user nice sys intr idle), memory from
  `hw.physmem` minus (`v_free_count` + `v_inactive_count`) × `hw.pagesize`, load from
  `vm.loadavg`, disks per ZFS pool (`zpool list -H -o name,capacity`) else `df` of `/` and
  `/home`, network from `route -n get default` + `ifconfig` ssid [BK; values checked on Linux
  only; FreeBSD: smoke test in the VM].
- **mixer(8)** (rewritten in FreeBSD 14): `mixer -o vol.volume` prints `vol.volume=L:R` (0.00 to
  1.00), `mixer -o vol.mute` prints `vol.mute=on|off`; `vol.volume=+5%` steps relative to 1.0,
  `vol.mute=toggle` [V: `usr.sbin/mixer/mixer.c` and `mixer.8`, releng/15.0].
- **clipmenu 6.2.0** runs `$CM_LAUNCHER` itself and adds `-dmenu` when it is exactly `rofi`;
  extra arguments go to the launcher; it copies the pick with `xsel` [V: clipmenu `clipmenu`].
- **i3lock-color** accepts every option `rice-session lock` passes (`--indicator --clock
  --radius --ring-width --{time,date,verif,wrong}-font --time-size --date-size --*-text
  --*-color -F`) [V: `i3lock.c` long options, 2.13.c.5; Xvfb smoke test]. Plain i3lock exits
  at once on those options, which would leave the screen unlocked: `rice-session` passes them
  only when `i3lock -v` names i3lock-color, else only `-i image -t`. `-n` keeps it in the
  foreground for xss-lock.
- **playerctl 2.3.1** has no `trunc()` in `--format` (2.4 has) [V: `playerctl-formatter.c`]:
  `rice-bar media` shortens titles itself.
- **libconfig (picom's format) rejects a trailing comma** after the last entry of a list
  `( ... )` ("line 44: syntax error", picom exits) [V: picom 10 / libconfig 1.7 in CI]. The
  `rules` list ends without one.
- **picom 13:** every top-level key and rule key the template uses exists in
  `src/config_libconfig.c` [V: picom main, 2026-10-27]. Without working OpenGL (VMs) picom exits
  on the glx backend; `rice-session x11` starts it again with `--backend xrender` (no blur).
- **Polkit agent in CI:** polkit-gnome starts but exits when there is no login session to
  register for (Xvfb, no logind/ConsoleKit session): the smoke test notes it instead of failing.
- **Polkit agent paths:** `/usr/local/libexec/` (FreeBSD [TODO-verify: smoke test in CI]),
  `/usr/lib/polkit-gnome/` (Arch [BK]), `/usr/lib/policykit-1-gnome/` (Ubuntu [V: dpkg -L]).
- **Suspend:** no logind, so nothing locks before sleep by itself; `rice-session power suspend`
  starts the lock first. `acpiconf -s 3` needs root on FreeBSD (unchanged from the Hyprland
  desktop).
- **What X11 cannot match:** the live ASCII sky and screensaver (Quickshell layer-shell
  surfaces), Hyprland's red-to-purple border gradient (i3 borders are one color: purple focus,
  red urgency), the bar's dropdown panels (output device picker, per-drive popups).

## Tests

- `tests/x11/smoke.sh` starts the installed session in Xvfb: i3, picom, dunst, xss-lock, polybar,
  polkit agent, clipmenud, every `rice-bar` value, a notification, and the lock screen (must still
  be up after 2 s), with screenshots. The FreeBSD VM job runs it after the real install
  (artifact `freebsd-i3-screenshots`).
- `tests/x11/run.sh` deploys the i3 files into a throwaway home with `lib/files.sh` and runs the
  smoke test; `ci.yml` runs it on Ubuntu 24.04 (i3 4.23, polybar 3.7.1, picom 10, dunst 1.9:
  older than FreeBSD's; picom 10 ignores `rules`).
- `tests/installer/verify-install.sh` (i3 desktop): commands, `i3 -C`, files, LightDM drop-ins,
  greeter theme, session entry, PAM line, `lightdm_enable`.
- Not testable in CI: LightDM itself (needs a VT and a real X server), Xorg on the GPU.

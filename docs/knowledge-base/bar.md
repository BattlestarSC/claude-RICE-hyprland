# Status bar: engines, data sources, the ASCII look

Concepts: [docs/bar/concepts.html](../bar/concepts.html) (generated by `tools/bar_preview.py`).
Inspiration: "Orbiter" by u/captianjonez on r/unixporn (KDE Plasma; ASCII shader wallpaper, custom
QML bar widgets, ASCII lock/login screens, one token file generating every theme).

## Requirements (owner, 2026-10-30)

RAM, CPU, load averages, audio (play/pause, **output device selection**, volume), network,
**disk usage per NVMe drive**. Plus, from the hardware: GPU (RX 6000), two monitors behind a KVM.

## Quickshell

## waybar

Verified against `Alexays/Waybar` man pages @ 2026-10-28 (0.15.0). [V: source]

- Has: `cpu` (`{load}`, `{load1}`, `{load5}`), `load`, `memory`, `disk` (**one instance per path**, e.g.
  `disk#home`), `network`, `wireplumber`/`pulseaudio`, `pulseaudio-slider`, `mpris`, `temperature`,
  `cpu-graph` and `custom-graph` (sparklines, new), `hyprland-workspaces`.
- `menu`: popups defined by a **static GtkBuilder XML file**. A live list of output devices is not
  possible there; selection would be a rofi script (`rice-menu`) on click.
- No dropdown panels with live data; tooltips only.
- Multiple bars per output via `"output"`; hot-plug behavior with 0.15: [TODO-verify].

## Decision (2026-10-30): Quickshell, Orbit Glass

Recommended Telemetry/Twin HUD; the owner picked **Orbit Glass** (D14). Engine reasons unchanged:
live dropdown panels and a native output picker are requirements; per-screen instances suit the
KVM; the same code can later provide notifications, OSD and an ASCII lock screen.

## Implementation (`config/quickshell/`)

```text
shell.qml            ShellRoot: Variants over Quickshell.screens → Wallpaper + Bar per monitor
common/              Config (sky mode/fps/periods, workspaces per monitor), Icons, Fmt
                     + Theme.qml deployed from themes/<palette>/quickshell/common/
services/            singletons: System, Audio, Media, Network, Bluetooth, SkyClock
bar/                 Bar (PanelWindow + PopupWindow), BarContent, panels, small widgets
sky/                 Wallpaper (Background layer), AsciiSky (two ShaderEffect passes)
```

- Imports use `import qs.common` / `qs.services` / `qs.bar` (Quickshell ≥ 0.2 maps `qs.*` to
  directories under the shell root) [V: source].
- Monitor ↔ bar: `Hyprland.monitorFor(screen)`; the primary monitor (workspaces 1–5) carries the
  telemetry pills; the secondary shows workspaces 6–10, title and clock. Clicking a workspace runs
  `Hyprland.dispatch('hl.dsp.focus({ workspace = N })')`; under 0.57 the dispatch string is a Lua
  expression [V: `usingLua` in source; exact behavior on hardware: TODO-verify].
- Layer namespaces: `rice-bar` (bar and its popups; blurred via `hl.layer_rule` in
  `config/hypr/conf/layers.lua`), `rice-sky` (wallpaper, no animation).
- Services are deliberately polling plain files (table below); Pipewire, MPRIS and BlueZ are event
  driven through Quickshell's own modules. Network uses `/proc/net/route` + `/sys/class/net` +
  `ip -j -4 addr`, so it works without NetworkManager.

### Notifications (D20)

- `services/Notifications.qml`: `NotificationServer` with `keepOnReload`, `persistenceSupported`,
  `actionsSupported`, `imageSupported`; body markup, hyperlinks and body images **not**
  advertised. Each new notification is `tracked` (kept after its popup), added to `history`
  (max 50; the oldest is expired), and shown as a popup unless do-not-disturb or the screensaver
  holds it (critical always shows). `lastGeneration` ones (re-emitted after a shell reload) go to
  history only. `transient` ones are never kept: expired when their popup closes.
- API facts [V: quickshell `src/services/notifications/*.hpp`, 9b0f339]: `expireTimeout` is in
  **seconds**; setting `tracked = false` equals `dismiss()`; the object is destroyed right after
  `closed` handlers return; apps may send markup even when it is not advertised, so every text
  uses `textFormat: Text.PlainText`.
- UI: `bar/NotificationCard.qml` (shared by popups and history), `bar/NotificationPopups.qml`
  (Overlay layer, namespace `rice-notifications`, sized to its stack so it never blocks clicks),
  `bar/NotificationsPanel.qml` (history, Quiet toggle, Clear all), bell pill with count.
- Primary monitor = leftmost screen (`services/Screens.qml`); `Quickshell.screens` order is not
  stable across KVM switches.

### Screensaver (D21)

`sky/SaverWindow.qml`, one per screen, hidden until `services/Screensaver.qml` is active
(`qs ipc call screensaver start|stop|toggle|isActive`; hypridle starts it at 5 min). Overlay
layer, exclusive keyboard focus (the dismissing key never reaches an app), opaque. AsciiSky with
the whole globe (radius 0.30 × height) and the canvas offset panning on a Lissajous path
(18 % × 12 % of the screen, 900 s loop), a clock on a separate 1300 s path, `saverFps` 8. It
votes in SkyClock, so it animates even in `still`/`image` wallpaper mode.
`tests/sky/render.py --saver` renders its framing.

### Testing without a compositor

`tests/quickshell/render.py OUT.png [--background frame.png]` loads the real bar QML through PySide6
(Qt Quick) with mock services (`tests/quickshell/mocks/`, same interfaces) and a stub `Quickshell`
module, and **fails on any QML warning**. Quickshell-only types (PanelWindow, PopupWindow, Pipewire,
Bluetooth, Hyprland) are therefore kept out of `BarContent` and the panels; only `Bar.qml`,
`Wallpaper.qml`, `shell.qml` and `services/` touch them and are untested off-hardware.

Pitfalls found that way: a custom property named `top` collides with Item's anchor line
("Cannot override FINAL property"); `implicitHeight` is read-only on `Row`/`Column`; a `Row` inside a
`RowLayout` collapses to its tallest child unless given `Layout.preferredHeight`.

## Data sources (no extra daemons)

| Metric | Source | Poll |
| --- | --- | --- |
| CPU % total and per core | `/proc/stat` deltas | 1 s |
| Load averages | `/proc/loadavg` | 1 s |
| Memory | `/proc/meminfo` (`MemTotal - MemAvailable`) | 1 s |
| Disk usage per drive | `lsblk -J -b -o NAME,PKNAME,TYPE,MOUNTPOINTS,FSUSED,FSSIZE`, partitions summed into their disk (`util-linux`, in `base`) | 30 s |
| Disk I/O per drive | `/proc/diskstats` sectors read/written deltas (×512 B) for `nvmeXn1`, `sdX` | 1 s |
| Network rates | `/sys/class/net/<if>/statistics/{rx,tx}_bytes` deltas | 1 s |
| Network details | default route from `/proc/net/route`; address from `ip -j -4 addr` | 10 s |
| GPU busy / VRAM / temp (amdgpu) | `/sys/class/drm/card*/device/gpu_busy_percent`, `mem_info_vram_used`, `mem_info_vram_total`, `hwmon/*/temp1_input` [BK] | 1 s |
| Audio, media, Bluetooth | PipeWire / MPRIS / BlueZ through Quickshell (event driven) | – |

All are plain file reads (QML `FileView`, or `Process` for `lsblk`/`ip`): cheap enough to poll at
these rates, once, from singletons shared by both monitors' bars.

## The ASCII look

- **Static (now):** `tools/spacegen.py <palette> ascii W H --cell 12x24` renders an Orbiter-style
  scene (planet with continents, clouds, atmosphere; moon; stars; nebula dust) as SVG text in the
  palette. Rasterize with `rsvg-convert` for hyprpaper, hyprlock and the ReGreet background, so
  wallpaper, lock and login share one grid like Orbiter's. Fonts must be installed when rasterizing.
- **Live (built, D15):** `config/quickshell/sky/`: a `Background`-layer window per monitor with
  two `ShaderEffect` passes (no camera tracking; the scene moves only with time).
  1. `scene.frag` runs on a cols × rows item (one fragment per character cell: 320 × 90 at
     4K with 8 × 16 logical cells at scale 1.5): ray-sphere for Earth and Moon, land mask texture
     (`assets/earth/land-1024x512.png`, from Natural Earth via `tools/earthmask.py`), ice caps,
     desert band, fbm clouds on their own rotation, day/night with city lights, atmosphere rim,
     tidally locked Moon, fixed-glyph twinkling stars, nebula dust. Output: rgb = color, a = ink.
  2. A `ShaderEffectSource` (nearest filtering, exact texture size) feeds `glyph.frag`, which picks
     one of 10 glyphs (` .:-=+*#%@`) from an atlas made by `bin/rice-sky-atlas` at the **physical**
     cell size (12 × 24 px at scale 1.5), so glyphs are pixel-exact, never scaled.
  - Time: `services/SkyClock.qml` computes angles from `Date.now() % 86400 s` in JS doubles and
    wraps them to [0, 2π) before they reach float uniforms; periods divide a day, so the animation
    is seamless across the wrap and identical on both monitors. 4 fps by default (`skyFps`).
  - Pauses: a monitor animates only while its workspace is empty (configurable), is hidden under
    a fullscreen window, and keeps its last frame otherwise; SkyClock's timer runs only while at
    least one monitor animates and the sky is not paused over IPC (lock screen). See "Cost".
  - Measured (llvmpipe, CPU): 200–474 ms per 4K frame; not representative of the GPU.

### Cost (2026-10-30; estimates, not measured on the target GPU)

Per 4K monitor and frame: scene pass ~28.8k cells × ~1k ALU ops ≈ 30 MFLOP; glyph pass 8.3M
pixels × ~20 ops + 2 texture reads ≈ 170 MFLOP and a 33 MB framebuffer write; then Hyprland
re-composites the output (reads that buffer, re-blurs the bar region). At 4 fps on two monitors:
≈ 1.6 GFLOP/s and ≈ 0.5 GB/s of memory traffic, against ~16–23 TFLOP/s and 512 GB/s on Navi 21
(RX 6800 / 6900 XT): well under 1 % of the GPU [arithmetic]. CPU: Quickshell sets four uniforms
and submits a handful of draw calls per frame; Hyprland renders the frame; both sub-millisecond
per frame [estimate]. Memory: window buffers ≈ 3 × 33 MB per 4K monitor of VRAM [estimate];
the static image modes need the same.

What actually costs: **waking the GPU 4–8 times a second** keeps it out of its deepest idle
states. On RDNA2 with two 4K panels the memory clock is usually pinned high anyway (display
timing needs it) [S: amd-gfx list and forum reports via search, 2024], so the increment is
likely small; measure, don't assume:

```sh
cat /sys/class/drm/card*/device/hwmon/hwmon*/power1_average   # µW; compare animated vs still
cat /sys/class/drm/card*/device/gpu_busy_percent
top -p "$(pidof quickshell),$(pidof Hyprland)"                # CPU per process
cat /sys/class/drm/card*/device/pp_dpm_mclk                    # is the memory clock pinned?
```

Controls (all in `~/.config/rice/settings.json`, live): `skyMode` `animated` | `still` | `image`,
`skyFps` (default 4), `skyAnimateWithWindows` (default false: animate only on an empty
workspace; otherwise the last frame stays and costs nothing), `skyLayout` `mirror` | `span`.
IPC: `qs ipc call sky pause|resume` (hypridle uses it while locked).

Why not a compiled CPU language: Zig/Rust/OCaml would have to produce the same 8.3M pixels per
frame on the CPU (llvmpipe, i.e. JIT-compiled SIMD, needs 200–474 ms per frame here) and upload
them. Why not a Rust *GPU* client (wgpu + layer-shell): same shaders, same compositor cost; its
one real advantage is partial damage (only changed cells are recomposited), which Qt Quick does
not do; not worth a second process and GPU context for a cost already under 1 %.
  - Unverified on a real Quickshell: frame callbacks while hidden, `ShaderEffectSource` with
    `hideSource` + `visible: false` inside a `PanelWindow` [TODO-verify on hardware].
  - Dev test: `tests/sky/render.py OUTDIR [--size WxH] [--dpr 1.5] [--frames N] [--span]`
    (PySide6 + Addons for `pyside6-qsb`, any OpenGL incl. llvmpipe).
- **Lock screen with the same grid:** Quickshell's session-lock module could replace hyprlock
  (ASCII clock included). Phase 3 option; hyprlock with the static ASCII image is the v1 path.

## Ideas adopted from Orbiter

- One token file → every theme: `colors/quasar.toml` already drives colors; extend it with
  `[fonts]` and `[sizes]` (bar height, gaps, radius, font sizes) when the bar is built.
- Variants that switch live: a pure-black variant is one `tools/blend.py` run away (darker base ramp);
  not planned unless asked.
- Same setup on several machines with per-machine monitors/scale: `local.lua` already planned.
